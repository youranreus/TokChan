# 本地与在线数据模式切换

## 目标
TokChan 支持本地与在线两套数据源，共用面板、菜单栏摘要及刷新流程；新增模式欢迎引导和应用配置重置。状态为 planning，等待最终方案审阅，未修改产品代码。

## 背景与证据
本机 Tokscale 4.15.1 graph 导出覆盖核心用量字段，118 个日桶、4 个客户端、60 个模型的汇总校验通过。读取会尝试价格更新及 Cursor 同步，网络失败可使用已有缓存。完整证据、代码落点与限制见 research/local-data-coverage.md。

## 需求与已确认决策
| ID | 合同 |
| --- | --- |
| R1 | 本地展示总 Tokens、成本、五类 Token 构成及客户端/模型明细，隐藏排名、活跃天数等在线指标。 |
| R2 | 本地面板手动刷新立即启动 Tokscale 本地读取，不执行 submit 或公开资料 API 请求。立即触发不代表同步瞬间完成。 |
| R3 | 右键菜单保留在线拉取和提交并拉取。 |
| R4 | 右键菜单新增软件名称与版本信息行、检查更新操作。 |
| R5 | 右键菜单和设置页提供共享持久化的本地/在线模式切换。 |
| R6 | 在线模式保留既有展示及面板提交再拉取语义。 |
| R7 | 本地模式允许 Tokscale 联网更新价格和同步 Cursor，不要求完全离线。 |
| R8 | 无保存模式时默认本地，适用于新安装及老用户；主动选择后重启恢复选择。 |
| R9 | 统一数据接口和刷新协调对象，仅数据源实现不同。保留现有五分钟后台刷新、唤醒检查、去重、新鲜度和失败退避流程；面板关闭时仍刷新当前来源。 |
| R10 | 本地模式执行右键在线操作只更新线上缓存，保持当前模式、面板和状态栏摘要，不将线上结果发布到本地展示。 |
| R11 | 初次欢迎页第一步选择模式，默认本地；本地直接进入面板，在线继续现有账号连接与首次提交流程。新增独立初始化状态，未记录该状态的老用户也显示欢迎页，保留已有配置。 |
| R12 | 设置新增清空 TokChan 配置按钮。清除 TokChan 偏好、初始化状态、两来源及旧版面板缓存，并关闭 TokChan 登录时启动；清空后重新进入欢迎页。保留 Tokscale 登录、用量、Cursor 缓存、自定义价格和自动提交配置。 |

## 技术与交互约定
- 周/月保持现有线上语义，即最近 7/30 天；本地按 Tokscale 统计时区确定今天，不能直接使用代表当月的 CLI --month，也不能用最后用量日充当今天。线上仍采用 API 返回的日期范围。
- 本地身份头部显示本地模式及读取时间，不要求或伪造在线身份。模式切换保留周期与展示过滤偏好。
- 本地选择进入即完成初始化，读取失败走面板重试，不要求先成功扫描。在线完成原引导后记录初始化完成；之后切换模式无需重复模式欢迎步骤。
- 清空先使旧请求失效并暂停刷新；失败显示具体错误并允许重试，不报告虚假成功。欢迎完成后恢复刷新。
- 旧 schema 2 快照只作为线上数据迁移，不能显示为本地用量。继续使用 macOS 标准偏好及 Application Support 存储位置。

## 验收标准
- AC1（R1、R9）：本地 Tokens、成本、构成与客户端/模型聚合匹配 fixture；四周期符合日期合同，覆盖午夜、无当日数据和空范围。
- AC2（R1、R2、R6、R7）：本地隐藏在线指标，面板刷新不上传或拉公开资料；在线面板保留提交再拉取。
- AC3（R5、R8、R10）：两个切换入口同步、重启恢复；缓存和异步结果按来源隔离，旧账号/请求不得覆盖新状态。
- AC4（R3、R10）：本地模式可执行在线菜单操作，结果只更新线上缓存；缺少在线账号时提供设置路径，不强制切换模式。
- AC5（R4）：名称和版本读取 Bundle；检查更新复用 Sparkle 更新器及 canCheckForUpdates。
- AC6（R2、R9）：缺少 CLI、解码失败、空数据及旧缓存可区分；失败不冒充零用量，保留合法旧快照。
- AC7（R9）：当前来源沿用 300 秒 TTL、30/60/300 秒失败退避及唤醒新鲜度检查；关闭面板不停止调度，自动路径不提交用量。
- AC8（R8、R11）：新安装和未初始化老用户先看到模式欢迎，本地无需账号进入；在线接续现有引导；完成后重启不重复欢迎。
- AC9（R12）：重置恢复默认及未初始化状态；内存、当前与旧磁盘缓存均清理，在途请求不能复活旧状态；Tokscale 文件与配置不变；失败可恢复。

## 范围外
不自建日志解析器、成本算法或上传调度器；不迁移到 ~/.tokchan；不清理 Tokscale 数据；不实际发布或修改版本号。本地模式不等同禁用已存在的 Tokscale 自动提交。

## 风险与实施验证
- 本机实测验证的是网络失败后的缓存回退路径，尚未完成所有客户端、首次无价格缓存及 CLI 空目录组合验证；实施阶段以固定 fixture 和隔离目录验证，并保留上游诊断，不保证缺价时成本完整。
- CLI 默认 latest 保持现有配置，4.15.1 为已验证基线。通过 graph/config 输出能力验证兼容性；不兼容时提示调整 CLI 版本，不静默伪造数据或自动修改用户版本。
- 原始 graph 不携带明确时区元数据，读取 config get timezone 获取统计时区。命令失败或时区无效不静默猜测，按本地来源错误处理并保留旧缓存。
- 清空涉及偏好、文件和系统服务，不存在跨存储原子事务；必须覆盖部分失败与重试。
