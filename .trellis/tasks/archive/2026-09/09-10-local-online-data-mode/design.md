# 双数据源设计

状态：实现与验证已完成；任务保持未归档。

## 统一接口
面板只依赖统一的 Dashboard 数据读取接口，返回包含四个周期的完整批次。本地实现调用官方 Tokscale graph 并聚合；线上实现适配现有 TokscaleAPIService。共同批次和展示数据不再强制依赖在线 username，身份信息与在线指标按数据源表达为可选能力，不伪造本地用户名或排名。

同一个协调对象负责加载状态、新鲜度、去重、五分钟调度、唤醒刷新、失败退避、周期选择和缓存发布，不复制两套 ViewModel。刷新策略共享；数据源实现承接各自读取工作。

## 操作语义
- 普通读取、自动刷新、重试按当前模式解析数据源，不上传。
- 面板主动刷新使用统一入口，保留来源特有的既有动作：本地立即读 graph；在线维持提交再拉取。
- 右键在线拉取/提交并拉取显式指定在线来源，不受当前选择影响；在本地模式下完成时仅写线上缓存，反馈仍可展示，但不切换面板或状态栏。
- 保留官方 autosubmit 配置与调度，不因为选择本地而禁用已有自动提交；数据展示模式与该既有功能分开管理。

## 缓存与竞态
缓存按来源隔离；线上缓存额外绑定规范化用户名，本地缓存不需要账号。请求记录来源及相关上下文代次，发布结果时再次校验；切换模式可以保留正确来源的后台完成结果，但不得发布到另一个来源的可见状态。账号、CLI 上下文变更不能接收过期结果。
升级 schema，旧 schema 2 数据只迁移为线上缓存，绝不冒充本地数据。无保存模式时默认本地；模式选择即时持久化。面板与菜单栏都由选中来源的批次派生；保留展示过滤配置。

## 本地导出
优先一次 graph 全量导出派生日/周/月/全部，避免四次扫描。允许上游价格更新和 Cursor 同步。复用 ProcessRunner、npx 定位、版本配置及取消/超时边界；分离 JSON 和诊断输出。真实成本继续由 Tokscale 计算。解析错误或 CLI 失败不生成零用量；已有缓存保持可见并标明过期/错误。
graph --no-spinner 的标准输出为 JSON，诊断走 stderr；复用现有进程超时（300 秒）和取消边界。读取 config get timezone 获取固定统计时区；日为该时区今天，周/月从今天向前包含 7/30 天，全部使用整个导出。时区读取失败或格式不支持时报可恢复错误，不猜测为主机时区。保留 latest 默认和用户版本选择，以命令/结构能力验证为准，不兼容时提示调整版本。空数据及缺少价格缓存组合在实施阶段用隔离目录/fixture 验证，缺价诊断不得伪装为精确成本。

## UI
右键菜单新增实际 app 名称与版本信息行、复用 AppUpdater 的检查更新行、当前模式选择项；设置提供同一偏好的模式控件。检查更新遵循 canCheckForUpdates，不创建第二套更新服务。
本地隐藏排名与活跃天数，保留 Tokens、成本、Token 构成及客户端/模型明细。模式切换保留周期和展示偏好。首次欢迎页先选模式，本地直接进入，在线接续现有引导。

## 变更边界
涉及 Dashboard 模型/协调对象、CLI 适配、偏好和缓存、Dashboard/Settings 视图、状态栏菜单及相关测试。API 线上合同维持不变。不新增日志解析器、成本算法、上传调度器或发布操作。

## 欢迎与初始化
新增独立持久化初始化标记，缺失视为未初始化，包括老用户升级。欢迎第一步默认选本地；用户选择本地进入即完成初始化，不以成功读取数据作为完成条件，CLI 错误在面板内恢复。在线分支保留当前账号和首次提交流程，并在该流程完成时标记完成。已有线上偏好和缓存不因首次显示新版欢迎页而删除。欢迎期间不自动触发上传或要求本地用户提供用户名。

## 清空配置
由显式重置入口统一处理偏好、初始化、缓存和内存状态，不能只是调用 save(defaults)。存储层需要 reset/clear 能力，同时删除 Application Support 当前快照及 Caches 旧快照，避免 legacy fallback 复活旧数据。先使在途请求失效并暂停后台刷新，再执行清理与状态重置；欢迎完成后恢复统一刷新。清理包含关闭 TokChan 登录时启动，调用已有服务并核对真实系统状态。失败可重试，不假定多个存储与系统服务存在原子事务。
Tokscale 的自动提交、自定义价格及登录属于共享上游状态，按用户确认不清除；按钮说明需清晰表达最终确定的范围。
