# 调整 Cursor 登录状态与欢迎页布局

## Goal

让设置页只在确实需要时提供 Cursor 自动登录，并在每次打开设置时反映最新会话有效性；同时修正首次欢迎页账号输入区的控件比例、对齐和空白，使操作层级清晰、视觉一致。

## Background

- 当前 `CursorLoginState` 只覆盖空闲、登录中、登录成功和登录失败，设置页始终渲染“自动登录”按钮（`TokChan/Shared/Components/CursorLoginView.swift:4-64`）。
- 设置窗口已通过 `settingsDidBecomeVisible()` / `settingsDidBecomeHidden()` 对连续可见周期去重，并在每次重新打开时刷新 autosubmit 状态，可复用同一生命周期边界（`TokChan/Features/Dashboard/DashboardViewModel.swift:276-287`）。
- 当前登录成功反馈保存在共享 ViewModel 中，关闭设置窗口不会清理 `cursorLoginState`。
- 欢迎页账号区的文本框没有与大号按钮统一高度；“继续”占满剩余宽度而“识别本机登录”按内容宽度布局，导致按钮大小不一致和视觉留白（`TokChan/Features/Dashboard/FirstUseOnboardingView.swift:107-139`）。
- Tokscale 当前提供 `cursor status`，会联网验证已保存会话；有效输出含 `Session: Valid`，无凭据或失效状态以普通文本表达，且该命令没有 JSON 参数。

## Requirements

### R1 设置页 Cursor 状态

- 每个新的设置窗口可见周期都执行一次 Cursor 状态查询；同一连续可见周期内由 `.task`、`.onAppear` 和 scene phase 引起的重复回调不得重复查询。
- 查询进行中的加载指示占用原“自动登录”按钮所在的标题行右侧位置，不在模块下方另起一行，并避免与登录等冲突 CLI 操作并发。
- 只有查询结果确认存在有效 Cursor 会话时，展示“已登录”状态并隐藏“自动登录”按钮。
- 设置页标题显示“Cursor 登录”，不带“（可选）”；引导页继续保留“（可选）”以表达其非阻塞性质。
- 设置页的“已登录”状态占用原“自动登录”按钮所在的标题行右侧位置，不在模块下方另起一行。
- 查询确认无凭据或会话无效时，展示“自动登录”按钮。
- 自动登录成功后立即投影为已登录状态，不额外执行 sync、submit 或统计刷新。
- 关闭设置窗口时清理本次登录成功提示；再次打开以新的 status 查询结果为准。
- 引导页仍保留可选的 Cursor 自动登录入口，不因设置页状态查询而成为阻塞步骤。

### R2 欢迎页账号输入布局

- Tokscale 用户名输入框与下方大号操作按钮具有协调且一致的视觉高度。
- “继续”和“识别本机登录”两个按钮等高、等宽，并占满同一行可用宽度。
- 清除由单侧弹性扩展或控件固有宽度造成的莫名空白，保持现有 380×680 固定视口内内容完整可用。
- 保留现有按钮主次层级、禁用条件、键盘默认操作、帮助文本和无障碍标识。

## Acceptance Criteria

- [x] AC1：首次打开设置触发一次准确的 `npx --yes tokscale@<version> cursor status`；不执行 shell，不触发 Cursor sync、submit、统计拉取或其他写操作。
- [x] AC2：同一连续设置可见周期的重复显示回调只查询一次；关闭后再次打开会重新查询一次。
- [x] AC3：设置页标题为“Cursor 登录”；状态查询中在原“自动登录”按钮所在的右侧位置显示加载指示；status 输出含有效会话标记时在同一位置显示“已登录”；两种状态都不显示“自动登录”或下方重复状态。
- [x] AC4：status 明确表示无凭据或会话已失效时，设置页显示“自动登录”按钮。
- [x] AC5：status 因网络、超时、版本不支持、输出格式变化或其他原因无法可靠判定时，只显示失败信息与“重新检查”，不显示“自动登录”。
- [x] AC6：自动登录成功后设置页立即切换到已登录投影；关闭设置后成功提示被清除，再次打开由 status 重新决定展示。
- [x] AC7：状态查询与其他显式 CLI 操作互斥，重复调用不会启动并发状态进程。
- [x] AC8：欢迎页用户名输入框与大号按钮视觉高度一致，两个操作按钮等高等宽且无异常留白。
- [x] AC9：欢迎页在 380×680 视口的正常、错误和繁忙状态下无裁切，既有交互与无障碍标识保持有效。
- [x] AC10：命令构造、状态解析、ViewModel 生命周期、固定尺寸布局及完整 macOS 测试通过。

## Constraints

- 继续使用现有原生 SwiftUI、共享 `DashboardViewModel`、Tokscale CLI 执行边界和 380×680 Dashboard 根视图。
- 不读取、记录或持久化 Cursor token/Cookie；状态仅来自 Tokscale 命令输出。
- 不新增登出、多账号切换或 Cursor 同步功能。

## Out of Scope

- 改造欢迎页其他步骤或整体视觉风格。
- 修改设置页其他 Tab、autosubmit 刷新语义或统计刷新调度。
- 在 TokChan 内管理 Cursor 凭据、登出、切换账号或执行显式同步。

## Key Decision

- Status 查询无法可靠判定时展示“状态检查失败”与“重新检查”，不展示“自动登录”；只有明确无凭据或会话无效时才提供自动登录入口。
