# 缓存与统一刷新设计

状态：已实施。需求依据 prd.md R1–R6；调研依据 research/cache-refresh.md。

## 数据边界
维持无外部依赖的 SwiftUI / ObservableObject / JSON 架构。API 服务提供整组读取能力：并发请求 all、week、month；同一个解码后的 week 响应派生 week 和 day，保留现有服务端日期规则。三次请求都成功并验证范围、账号后返回完整统计集合。请求要有有限超时，不允许慢请求永久占用批次。

完整统计值作为单个可观察快照发布，含 username、四范围映射、generation、fetchedAt；源数据 updatedAt 与客户端 fetchedAt 分开。界面“更新于”表示最近成功读取时间，详情说明含义，不冒充最近提交时间。identity、当前范围统计及获取时间由同一快照派生，避免多个 Published 属性依次造成中间混合状态。

自动提交状态独立保存 observedAt 和错误，同轮触发但不参与统计成功门槛；统计和状态分别完成时合并写入当前最新内存快照，避免互相覆盖。CLI 上下文变化使旧状态请求失效。

## 刷新调度
- 注入时钟/调度接口供确定性测试，默认窗口 300 秒。
- 面板显示：同步已有快照；完整批次未过期则复用，缺失或过期则发起一次静默读取。持续可见时每 300 秒尝试一次；关闭取消后续定时触发。
- 关闭允许已经开始且有超时的批次完成，防止快速开关反复取消；任务由 App 持有的模型管理，不依赖视图 .task 的存活。
- 唤醒/再次显示重新计算新鲜度，不累计补跑睡眠期间定时事件。时钟回拨导致负年龄时重新验证。跨日且日期判断有可靠依据时可提前只读校验，但实际数据日期始终采用服务端范围；显示实际缓存日期避免误导。
- 同时最多一组统计读取；重复自动触发共享正在进行的任务，失败不更新时间，下次可见定时重试。为避免开关面板请求风暴，失败自动重试至少间隔 30 秒；手动行为不受此冷却限制。
- 切换范围不改变批次 generation，不启动独立范围请求；缺失旧范围展示真实加载/错误状态，共用整组补齐。
- 手动提交开始时使提交前读取批次失效/取消；操作期间暂停自动触发，提交成功后强制全组重读，不能复用提交前请求结果。提交失败保留快照。run-now、设置保存后的相关重读共用整组入口。
- 账号变化先隔离旧快照、递增 generation，再加载新账号；迟到结果不能回写内存或磁盘。无用户名时仅在既有身份发现流程中调用 whoAmI，绝不隐式上传。

MenuBarExtra 可见性必须用实际面板生命周期验证；不能把设置窗口活跃或任意 scenePhase 活跃当作菜单面板可见。优先既有 SwiftUI 生命周期；若无法可靠覆盖显示/隐藏，用局限于面板的最小 AppKit 桥接，保持 macOS 13 支持。

## 持久化与迁移
最后成功展示快照保存至 Foundation 返回的 Application Support/com.youranreus.TokChan/dashboard-snapshot.json，使用显式 schemaVersion。新路径优先；没有有效新快照时只读兼容旧 Caches 路径。迁移写入成功前不删除旧文件；不对原始记录或凭据做任何迁移。

兼容当前 profiles 及更早有 period 的单 profile。只有四范围完整且来自新批次的数据才能带完整批次 fetchedAt；旧范围有独立时间，不推断成同批或新鲜。暂时保留旧范围及各自日期供查看，一次成功整组读取后升级。无 period 的旧格式不可安全解释，按无缓存处理。

保存选择不改变 fetchedAt。保存状态不改变统计 fetchedAt。写失败保持原子替换前文件，内存显示成功值并记诊断；恢复新快照失败时允许读取仍有效旧文件，不覆盖损坏文件为空数据。

## 展示与反馈
保留 380×680 布局。复用底部或现有状态区域显示低对比度更新时间及可点开的详情；跨日旧数据明确显示实际日期。没有变化的统计不做数字或布局动画，刷新不重置当前范围及同范围展开/滚动状态；主动切换范围仍遵守原有重置行为。

有数据时后台读取不改变提交按钮进度或显示结果横幅。主动提交/运行/保存保留现有操作反馈，且区分命令成功但整组读取失败。无任何可展示数据时仍提供加载或错误重试入口。详情区区分统计读取、状态读取与持久化失败；旧 autosubmit 状态可通过观察时间辨认。

## 兼容性、取舍与回滚
新策略明确替换 data-persistence.md 中“有缓存永久不读”“提交只读当前范围”和 swiftui-guidelines.md 中“后台读占用按钮”的旧约定；实施完成后同步规范与对应测试。

不依赖远端提供同版本快照；不从 HTTP 成功推断数据已包含刚提交用量。实施时用 URLProtocol 等测试确认请求缓存策略，明确只读更新会要求 HTTP 重验证或绕过本地响应缓存；不需真实提交验证。

本次只调整展示层缓存和请求调度，不变更远端数据或 CLI 配置。回滚代码时新路径文件可留存，旧版本仍可读取旧缓存；旧文件不自动删除。遇不支持 schema 按无有效新快照处理。
