# 统一浮窗文案与菜单交互

## Goal

消除浮窗内重复且语义不同的更新时间，精简底部操作栏，并让手动操作反馈具有清晰、可预测的生命周期；同时统一“关于”页品牌介绍。

## Background and Confirmed Facts

- 当前浮窗头像下方显示 `@用户名 · 线上更新于 …`，来源是服务端资料的 `profile.updatedAt`。
- 当前底部显示 `数据日期 … · 更新于 …`，其中“更新于”来源是最近一次完整统计快照成功获取并保存的 `cacheSavedAt`；跨日时附服务端统计范围的结束日期。两者含义不同，造成准确性判断歧义。
- 底部操作栏当前包含“设置”、快照更新时间、刷新诊断入口和“退出 TokChan”。
- 菜单栏入口当前使用 SwiftUI `MenuBarExtra` 的 `.window` 样式，仅声明左键浮窗，尚无右键菜单实现。
- 手动提交、立即运行自动提交和保存设置会把结果写入 `DashboardViewModel.operation`；现有 `clearOperationMessage()` 可清除结果，但浮窗关闭时没有调用，因此成功或失败横幅会跨关闭保留。
- 上一项缓存任务已约定：界面的统一“更新于”应表示最近一次成功读取完整统计的时间，不冒充提交时间；跨日旧数据需显示服务端实际数据日期。
- 当前“关于”文案为“TokChan 是 Tokscale 的 macOS 菜单栏伴侣，用于查看用量并管理自动提交。”，作者链接尚不存在。

## Requirements

| ID | Requirement |
| --- | --- |
| R1 | 只保留一套无歧义的数据新鲜度说明，以最近一次完整统计快照成功获取时间为准；跨日旧数据同时标明服务端实际数据日期，不再把 `profile.updatedAt` 与本地获取时间并列为两个“更新于”。 |
| R2 | 移除浮窗底部操作栏；将“设置”“退出 TokChan”、统一更新时间和刷新诊断集中到菜单栏图标右键菜单；浮窗标题区同时低调展示同一套更新时间/数据日期说明。 |
| R3 | 浮窗关闭后，已经结束的手动操作成功/失败提示自动清除；进行中的操作不被取消，完成后再次打开不展示上次遗留横幅。 |
| R4 | “关于”介绍显示两行：第一行“Tokscale的状态栏预览应用”，第二行“Made with love by 季悠然”；“季悠然”可点击并打开 `https://blog.mitsuha.space`。 |
| R5 | 保持 macOS 13 支持、原生菜单栏窗口体验、现有 380×680 浮窗尺寸，以及现有手动提交、设置和退出行为。 |

## Acceptance Criteria

- [x] AC1：头像区不再显示服务端资料的 `profile.updatedAt`；浮窗标题区与右键菜单仅显示同一套统计快照获取时间，跨日旧数据同时显示实际数据日期。
- [x] AC2：浮窗底部不再存在独立操作栏，也不再承载“设置”、更新时间、刷新诊断或“退出 TokChan”。
- [x] AC3：右键点击菜单栏 TokChan 图标可查看统一更新时间、在有诊断时访问刷新详情，并可执行“设置”和“退出 TokChan”；对应行为与迁移前一致，左键仍打开/关闭统计浮窗。
- [x] AC4：手动操作完成后的成功或失败横幅在当前浮窗保持打开时仍可见；关闭并再次打开后不再显示上次结果。关闭浮窗不会中断正在执行的操作。
- [x] AC5：“关于”页按指定内容换行显示，点击“季悠然”使用系统默认浏览器打开指定 HTTPS 地址。
- [x] AC6：132 个单元测试与 Release/Analyze 通过；状态栏 UI 自动化因 SystemUIServer 不暴露状态项而跳过，左右键、原生状态栏菜单和设置打开已由用户在本地 Release 构建中手动验收。

## Out of Scope

- 不改变静默刷新、缓存 TTL、完整批次一致性、远端 API 或 CLI 提交逻辑。
- 不新增刷新频率设置、通知中心通知或定时自动隐藏横幅。
- 不重设计设置页其他分区、统计卡片或时间范围选择。
