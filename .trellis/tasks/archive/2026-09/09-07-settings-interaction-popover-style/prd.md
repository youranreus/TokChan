# 调整设置交互与浮窗样式

## Goal

让设置窗口的生效时机清晰、信息分组符合用户认知，并使状态栏浮窗的箭头与内容背景在明暗外观下保持一致；同时删去不产生决策价值的辅助文案。

## Background and Confirmed Facts

- 本任务直接从 `master` 创建工作分支并以 `master` 为 PR 目标。状态栏文案功能当前只存在于已完成的 `feat/status-text-and-actions` 提交序列；执行时先把该序列纳入新的 master-based 任务分支，再实施本次细化，避免让最终交付依赖该功能分支。
- 现有全局“保存”按钮由 `SettingsView.settingsPage` 提供，出现在“常规”“自动提交”和“关于”Tab；“自定义价格”Tab 使用独立的即时落盘流程。
- 点击全局“保存”会一次提交常规偏好与自动提交配置：校验用户名、版本和 npx 命令上下文，启用或禁用 CLI 自动提交，持久化用户名、Tokscale 版本、npx 路径、状态栏文案开关/模板/范围，随后强制刷新全部统计和自动提交状态；全部成功才关闭设置窗口。
- “登录时启动”开关不经过全局“保存”，而是切换时立即调用系统登录项注册/注销；自定义价格也不经过全局“保存”。因此当前按钮名称和出现范围不能准确表达它实际影响的设置。
- Apple macOS HIG 的 Settings / Buttons / Sheets 指引整体倾向普通设置直接生效，不在设置窗口长期放置笼统的 Save / Apply / Cancel；只有需要验证、成本较高、影响显著或必须原子提交的编辑才适合显式确认。用户已选择“分层即时生效”：普通本地偏好直接持久化，CLI 自动提交配置保留独立确认。
- `feat/status-text-and-actions` 的常规页当前顺序为“资料与命令行 → npx → 状态栏文案 → 启动”，与目标顺序不同。
- 状态栏文案当前说明为“支持 {token} 与 {cost}；其他内容会原样显示。”；用户希望只保留受支持模板变量的信息。
- 登录项区当前在正常启用、未启用及未建立记录时显示说明性状态文案；切换进度、失败原因及系统要求人工批准时的恢复入口属于操作反馈，不应随普通说明一并删除。
- `DashboardView` 显式使用不透明 `.background(.background)`，而外层 `NSPopover` 已由 AppKit 提供系统 popover visual-effect surface 和箭头，因此形成了透明度不一致的两层背景。

## Requirements

| ID | Requirement |
| --- | --- |
| R1 | 删除跨 Tab 的全局“保存”栏。常规本地偏好在控件值变化时直接写入现有 `UserDefaults` 偏好并发布到共享模型，不执行 CLI 自动提交配置、不提交用量、不强制拉取统计，也不自动关闭设置窗口。 |
| R2 | “自动提交”Tab 保留独立的显式操作，命名为“应用自动提交设置”；它只应用当前自动提交表单并重读自动提交状态，不保存常规草稿、不提交用量、不拉取统计，也不关闭设置窗口。“关于”Tab 不显示提交操作。 |
| R3 | 用户名真正变更时立即隐藏并失效旧账号统计，避免状态栏或浮窗继续显示另一账号数据；不因每次文本输入启动网络请求。Tokscale 版本和 npx 路径变化只影响后续 CLI 操作，不清空与其无关的远端统计缓存。 |
| R4 | “常规”Tab 的 Section 固定排序为“基本配置”（由“资料与命令行”更名）→“状态栏文案”→“启动”→“npx”。 |
| R5 | 状态栏文案说明只显示“支持的模板变量：{token}、{cost}”；不再展示未知内容处理等额外说明，既有未知占位符原样保留的运行语义不变。 |
| R6 | 登录时启动区移除 enabled、notRegistered、notFound 三种普通状态的说明文案；保留切换中的进度、错误反馈，以及 `requiresApproval` 状态下必须的系统批准提示和“打开系统设置”入口。 |
| R7 | 浮窗内容不再以纯白/纯色根背景覆盖系统 `NSPopover` 材质；箭头与内容主体在浅色、深色外观下应呈现连续一致的系统浮窗背景，同时保持现有 380×680 尺寸与内容布局。 |
| R8 | 保持状态栏文案模板渲染与统计范围、左右键菜单、登录项注册、自定义价格及自动提交业务语义不回归；本次不新增功能。 |

## Acceptance Criteria

- [ ] AC1（R1、R2）：常规改动直接持久化并及时反映到依赖已保存偏好的界面；常规与关于页没有全局“保存”，自动提交页只显示“应用自动提交设置”，任何设置操作都不因成功而关闭窗口。
- [ ] AC2（R1、R2）：常规改动产生零 autosubmit configure/disable、零 submit、零 profile fetch；应用自动提交只执行一次对应 configure/disable 和一次 status read，产生零 submit、零 profile fetch，且不推进统计快照 `fetchedAt`。
- [ ] AC3（R3）：用户名切换后旧账号数据立即不可见，旧请求不能晚到发布，持久化快照不再包含旧账号 profiles；逐字编辑本身不触发网络。版本或 npx 路径变化继续保留当前统计缓存。
- [ ] AC4（R4）：常规页从上到下依次显示“基本配置”“状态栏文案”“启动”“npx”，无其他 Section 插入其间。
- [ ] AC5（R5）：状态栏文案区只显示“支持的模板变量：{token}、{cost}”；运行时仍只替换这两个变量并保留未知内容。
- [ ] AC6（R6）：登录项处于 enabled、notRegistered 或 notFound 时不显示额外说明；更新、失败和 requiresApproval 时仍提供完成操作所需的反馈或入口。
- [ ] AC7（R7）：真实状态栏浮窗在浅色与深色模式下，箭头和主体背景没有明显透明度或色值断层；现有尺寸、圆角、阴影和点击外部关闭行为不变。
- [ ] AC8（R8）：自动提交异步状态首次到达时可初始化尚未编辑的表单，但不得覆盖用户已经编辑的草稿；登录项、自定义价格、状态栏左右键和状态文案不回归。
- [ ] AC9：相关单元测试、UI smoke test、Release 构建、Analyze 与 `git diff --check` 通过；真实状态栏浮窗和设置页完成手动视觉验收。

## Out of Scope

- 新增状态栏模板变量、模板校验、预览或格式化选项。
- 重做整个设置窗口导航、自动提交业务、自定义价格编辑器或 Dashboard 内容布局。
- 自绘 popover 箭头、窗口阴影、圆角或叠加第二层自定义材质。
- 修改缓存 schema、Tokscale API、提交/拉取命令和状态栏右键菜单功能。

## Risks and Deferred Items

- 用户名文本逐字变化会尽早隐藏旧账号数据，这是防止跨账号误显的安全取舍；新账号数据沿用现有面板加载或显式拉取路径获取，不新增输入防抖网络请求。
- 自动化布局测试无法证明系统箭头和主体的像素连续性，浅色与深色真实 `NSPopover` 仍需要人工验收。
