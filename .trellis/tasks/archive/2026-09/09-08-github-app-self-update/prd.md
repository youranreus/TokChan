# 实现 GitHub 应用内检查更新与自更新

## Goal

让已安装的 TokChan macOS 应用能够从设置页主动发现 GitHub 上的新版本，并在不要求用户手动访问浏览器、下载和替换应用的情况下完成安全更新。

## Background

- 应用已经具备 Apple Developer ID 签名与公证发布流程。
- 当前发布流程通过 GitHub Releases 提供 Developer ID 签名、Apple 公证并装订票据的 universal DMG 及 SHA-256 文件。
- 项目当前未集成 Swift Package，也未生成 Sparkle appcast 或 EdDSA 更新签名。
- 更新包托管在 GitHub Releases，appcast 与发布说明托管在项目 GitHub Pages 的固定 HTTPS 地址。
- 用户入口位于设置页面的“关于”标签下方。

## Requirements

- 在设置页面“关于”标签底部增加“检查更新”按钮。
- 首版仅支持用户主动点击按钮检查更新，不在启动时或后台自动检查。
- 使用 Sparkle 2 实现版本发现、更新包验证、安装、回滚保护与重启；不自研应用替换器。
- 发布流程生成 Sparkle appcast 与 EdDSA 签名更新包；更新 ZIP 发布到 GitHub Releases，feed 部署到 `https://youranreus.github.io/TokChan/appcast.xml`。
- 点击按钮后由 Sparkle 查询稳定版更新，并使用 Sparkle 标准更新窗口承载检查结果、版本说明、用户确认、下载/安装进度与错误反馈。
- 没有新版本时，标准窗口明确反馈当前已是最新版本。
- 有新版本时，标准窗口展示版本号与发布说明；仅在用户二次确认后下载并执行自更新。
- 下载、校验、安装或重启失败时，标准窗口给出可理解且可恢复的错误反馈。
- 更新机制不得绕过现有 Developer ID 签名与公证安全边界，并额外使用 Sparkle EdDSA 更新签名。
- 检查与更新流程由 Sparkle 串行管理，按钮可用性与框架状态同步，避免重复触发。

## Acceptance Criteria

- [ ] 设置页“关于”标签底部显示可用的“检查更新”按钮。
- [ ] 点击按钮后，Sparkle 标准更新窗口能从项目托管的 appcast 获取适用于当前应用的最新稳定版本。
- [ ] 远端版本不高于当前版本时，标准窗口明确显示“已是最新版本”等等价结果。
- [ ] 远端版本更高时，标准窗口展示版本号和发布说明，并仅在用户确认后开始下载。
- [ ] 更新包下载成功后，Sparkle 能校验并安全替换已安装应用，然后使用户进入新版本。
- [ ] 网络、feed、版本元数据、更新包缺失、下载、EdDSA/代码签名校验、安装和重启失败均不会破坏当前可运行版本，并由标准窗口给出明确错误提示。
- [ ] 更新流程进行时不能从“关于”页重复启动第二次检查或安装流程。
- [ ] 发布流程为稳定 Release 生成并发布可用 appcast、EdDSA 签名更新包，同时保留现有已签名/公证 DMG 与 SHA-256 发布物。
- [ ] 自动化测试覆盖更新入口接线、按钮禁用逻辑与发布/feed 生成契约；项目现有检查保持通过。

## Out of Scope

- 启动时静默检查、定时检查、后台检查及对应提醒去重。
- 自研下载、应用替换、回滚和重启机制。
- 支持预发布版本或更新通道选择。
