# 自动探测 npx 路径

## Goal

让 TokChan 默认自动找到可用的 `npx`，普通用户无需理解或手工填写可执行文件路径；仅在自动探测失败或需要覆盖时提供清晰的恢复入口。

## Background

- `NpxLocator` 已会依次检查已保存的绝对路径、进程 `PATH`、Homebrew/系统固定路径和 `~/.nvm/versions/node/*/bin/npx`。
- `DashboardViewModel.commandContext` 在偏好路径为空时已经调用自动探测。
- 当前设置页仍把“npx 可执行文件”呈现为普通文本输入框和“选择…”按钮，没有说明留空即自动探测，因而让用户误以为必须手工配置。
- 现有集成规范要求保留可选的绝对路径覆盖，以处理自动探测失败的安装方式。

## Requirements

- R1：未配置覆盖路径时，应用自动探测可执行的 `npx` 并用于 Tokscale 命令。
- R2：设置页默认表达“自动探测”状态，不要求普通用户输入路径。
- R3：保留自动探测失败时的手动选择能力；保存的覆盖路径仍须由现有命令上下文校验为绝对、可执行文件。
- R4：界面应能展示当前自动探测结果或探测失败状态，避免用户猜测应用实际使用的路径。
- R5：不改变 Tokscale 命令参数、安全边界或偏好数据的兼容性。

## Acceptance Criteria

- [x] 首次使用且 `npxPath` 为空时，常见 PATH、Homebrew 和 NVM 安装可被自动找到，无需设置。
- [x] 设置页明确显示自动探测状态及实际探测到的路径。
- [x] 用户可在自动探测失败时选择自定义 `npx`，也可清除覆盖并恢复自动探测。
- [x] 已保存的有效自定义路径继续优先于自动探测，失效覆盖不会阻止回退到其他候选。
- [x] 自动探测与设置交互有覆盖测试，现有测试继续通过。

## Out of Scope

- 自动安装 Node.js/npm/npx。
- 执行交互式 shell 或读取 shell profile 来推断 PATH。
- 改变 Tokscale 版本、登录或自动提交行为。

## Key Decisions

- 手动覆盖入口按需展开：自动探测成功时默认只显示状态与实际路径；用户需要特殊安装覆盖或探测失败时，可展开并选择自定义可执行文件。
- 保持现有偏好字段兼容；空值表示自动探测，有效绝对路径表示用户覆盖。
